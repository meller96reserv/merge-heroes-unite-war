# TASK-0042 — Bounded bridge fixture contract

This spike uses the production v1 envelope and the existing game.ready/app.initialize payloads. Its additional probe.ping/probe.pong/probe.color/probe.report types exist only inside the spike schema and projects. They neither extend the production message catalogue nor authorize gameplay/economy operations. Production schema generation and the full feature catalogue remain their own DAG tasks.

Both receiving JS runtimes use the same pure TypeScript validator/receiver. It enforces exact fields and typed payloads, UTF-8 size≤65536 bytes, protocol version1, session/generation identity, monotonic sequence, request fingerprint/idempotency and bounded request storage. Unknown/malformed/stale/duplicate/conflicting/out-of-order messages do not invoke the fixture color callback. Duplicate identical requests return a cached classification and do not repeat the effect; capacity exhaustion requires a fresh session rather than evicting idempotency records.

Native adapters carry strings through the pinned Cocos JsbBridge and generated RN TurboModule events. Native byte limits and active-owner checks run before engine delivery. Android schedules on the Cocos game thread; iOS uses the main thread where this exported engine runs. RN events enter its JS queue. No evalString interpolation and no per-frame bridge traffic are needed.

Expected native oracles: Cocos ready reaches RN; matching initialize returns to Cocos; a Cocos ping reaches RN; RN sends one color command; Cocos changes color exactly once and reports it. Each receiver executes invalid JSON, unsupported version/type, invalid payload, stale generation/session, reordered sequence and duplicate/conflicting request cases. Transport oversize is rejected before engine entry; receiving-runtime size validation is also exercised with the same pure validator. All failures/results and runtime thread logs must be captured before completion.

Primary API sources checked against installed code: [Cocos Java bridge](https://docs.cocos.com/creator/3.8/manual/en/advanced-topics/js-java-bridge.html), [Cocos Objective-C bridge](https://docs.cocos.com/creator/3.8/manual/en/advanced-topics/js-oc-bridge.html), [RN generated native events](https://reactnative.dev/docs/the-new-architecture/native-modules-custom-events). These APIs expose transport primitives; native test evidence is still required. [Production contract](../../docs/technical/18_BRIDGE_PROTOCOL.md) · [NAT acceptance](ACCEPTANCE.md).
