# ADR-007 — React Native game runtime with Skia

Status: ACCEPTED by explicit user direction, 2026-09-09. TASK-0252 owns this targeted amendment. Supersedes ADR-001, ADR-002 and ADR-006 production strategies. Historical evidence is retained under `spikes/rn-cocos/`; checkpoint `18cad48` contains the bounded audio probe. Its physical acceptance remains PARTIAL, never retroactively PASS.

The game is implemented in React Native + TypeScript. Use Expo where compatible, @shopify/react-native-skia for the shared real-time 2D surface, react-native-reanimated for high-frequency presentation and UI animation, and react-native-gesture-handler for input. One application, one pure game-core and one semantic asset registry serve Android, iOS and Web. Root `npm run dev:web` launches this application with Fast Refresh. Browser-specific code is limited to runtime initialization and platform services, including CanvasKit loading; it cannot fork gameplay or visual composition.

Ownership: game-core owns deterministic rules, authoritative state, exact currency, damage, merges and durable reward receipts. RN owns application composition, routes, safe areas, AppState and platform service adapters. Skia projects state; Reanimated values and gesture callbacks carry presentation changes. A completed gesture submits one typed domain command. Animation/VFX/audio completion never changes rewards or damage. Domain ticks remain bounded and deterministic; UI worklets must not own economy. Measure JS/UI frame cost before optimizing or relocating simulation.

Preserve existing Figma analysis, semantic mappings, screen specifications, reference evidence, balance observations, domain and recovery contracts. Old `targetPath`/`prefabUsage` metadata in immutable Figma analysis remains provenance; the runtime importer maps semantic IDs to app assets without requiring engine UUIDs. Preserve exact canonical Figma fixtures separately from the 15-slot adaptation.

Execution priority: foundation/browser → Skia surface → battle HUD/board/layout → purchase/spawn/drag/merge → battle/enemies/projectiles/rewards → stages/bosses → motion/VFX/audio → save/offline integration → remaining screens → Android/iOS validation and optimization. Core transaction safety is never deferred; early acceptance uses deterministic storage fakes and the web store, while exhaustive offline/device parity is later. Exact hidden reference formulas remain UNKNOWN; explicitly versioned PROPOSED product rules with owning-task tests may ship within the authorized approximation scope. Rights, save safety and actual release validation still apply.

Retire production engine hosting, native engine ownership and serialized host/game protocol. TASK-0037…0046 are historical; completed tasks retain evidence, incomplete 0044/0046 are SUPERSEDED. No active task may depend on them. TASK-0201…0212 now validate RN application platform services and native builds. This removes an obsolete strategy gate, not native QA. Web results prove only Web.

Acceptance: migrate affected requirements and dependencies only; preserve unrelated product data; zero dangling dependencies, no active dependency on historical tasks, zero production requirements for the retired engine, acyclic executable DAG and consistent task/phase references. Commit this amendment before implementing TASK-0047. No planning-package regeneration or production quality reduction.
