# Repository structure

Root package.json, package-lock.json, app.json, babel.config.js and metro.config.js define one Expo application. `index.ts` / `index.web.ts` differ only in runtime initialization. `app/src/{screens,components,rendering,input,animation,audio,platform,debug}` contains the shared React Native game; `app/assets/{art,audio,game-data}` contains generated semantic runtime assets. Root native folders are generated by Expo prebuild when needed; source config/plugins are versioned.

`game-core/src/{model,commands,systems,events,ports,selectors,config}` and its tests are strict pure TypeScript. No React Native, Skia, browser globals or presentation packages may be imported. `tooling/{assets,config,visual,balance,ci}` and `tests/{integration,e2e,goldens,native}` hold importers and acceptance harnesses. The isolated historical spike is outside the production import graph.

Root npm commands: `dev:web` starts Expo Web with Fast Refresh; `typecheck` checks application sources; `build:web` exports the same application. TASK-0048 adds build:core and the enforced domain boundary; TASK-0053 adds the core/data CI pipeline. Dependency versions are pinned to a verified Expo compatibility set with a committed npm lockfile. Do not claim a command works before its task evidence exists.

Keep source documents, semantic IDs and calibrated alpha/trim metadata. Runtime import paths derive from semantic IDs; original analysis paths are provenance. No engine metadata files are needed. Ignore dependencies, generated native/build products, CanvasKit copies and private signing material.
